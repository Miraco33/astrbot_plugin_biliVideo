## 已确认的上游源码风险

基线：storyAura/astrbot_plugin_biliVideo@7cfb5ef0c365e35949e8afd5ff0eca7a513924cb。

1. 下载器未显式设置有限下载/分片/提取重试；网络中断会进入失败路径。
2. 必剪使用普通 requests.Session，各阶段单次请求异常会终止处理；错误记录可能带完整 URL。
3. scheduled_push 将总结异常转换为错误提示；发送后仍可能推进 last_bvid，造成该视频不再自动补总结。
4. scheduled_push 未检查 send_message 的布尔返回值；无异常不等于发送成功。
5. 音频质量选项用于下载后的转码，源下载仍选择 bestaudio；降低该选项不能直接降低源文件下载量。
6. 现有 TaggedLogger 没有统一脱敏；原始异常和目标标识不得直接用于公开诊断。

这是代码静态风险，不证明当次云端游标已经推进，也不证明仓库已经发生凭据泄露。

## v2.2.0 修复范围

本轮按可复现代码路径补充模拟测试；真实外部服务和 QQ 客户端验收另列，不能用 CI 结果替代。

| 项目 | 已实现行为 |
|---|---|
| 下载中断 | 有限网络/分片重试、续传、媒体地址刷新与取消清理；质量档位参与源音轨选择 |
| 必剪转写 | 请求阶段、异常类别和 HTTP 状态分开；有限恢复、取消及整体预算；412 单独归类 |
| 长视频 | 可配置下载/转写时限、音频时长和大小上限，超限明确停止 |
| 备用 ASR | 可选已有 AstrBot 语音转写提供商；默认空值关闭，不新增凭据或依赖 |
| 订阅补偿 | 摘要、失败通知和各目标确认分开保存；失败不推进完成游标；重试复用已生成摘要 |
| 投递结果 | 只接受明确 True 的发送返回值；成功目标不重复投递；有限自动重试后保留任务供 /检查更新 |
| 工具回传 | 新增 bilibili_search_result；任务按原会话隔离，可分段读取完成内容及失败/取消状态 |
| 卡片识别 | 直接 Json 卡片与引用卡片统一解析；无效/过长 BV 不再截断后请求元数据 |
| 诊断隐私 | 统一运行日志脱敏、异常安全摘要，保留阶段/类型/状态，隐藏认证信息和完整目标 |

工具任务完成后需要模型调用结果工具；没有接入不稳定的后台唤醒接口，不承诺自动恢复已结束的模型轮次。
发送成功与持久化回执之间仍有不可原子化的崩溃窗口；平台返回成功也不能证明客户端已收到。
旧版本已经推进的游标无法凭现有记录自动恢复；不要猜测或倒退生产游标，历史失败视频用 /总结 单独重试。
历史 code=-400 的真实输入仍未知；本轮只关闭已复现的输入解析缺陷，不把它写成历史故障的唯一根因。
